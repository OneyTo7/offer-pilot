# PRD：面壁（OfferPilot）— AI 简历智能平台

> 版本：v0.2
> 日期：2026-08-31
> 状态：初稿
> 定位：企业级个人作品项目（技术投名状）

---

## 1. 产品概述

### 1.1 产品定位

面向技术研发岗位求职者的 AI 简历分析 + 面试模拟平台。用户上传简历、设定目标职位，AI
生成匹配度评估报告，并提供简历优化建议和模拟面试训练。

### 1.2 产品 slogan

**"让每一次面试都更有准备"**

### 1.3 核心价值

- 知道简历和目标岗位差在哪（诊断）
- 知道面试会被问什么，提前练（训练）

---

## 2. 用户画像

### 2.1 目标用户

技术研发岗位求职者，覆盖全职级：

| 类型        | 特点           | 核心需求           |
|-----------|--------------|----------------|
| **应届生**   | 简历内容少，面试经验不足 | 简历怎么写、面试问什么    |
| **1-5年**  | 有一定项目经验，想跳槽  | 简历优化、技术面准备     |
| **5-10年** | 资深开发/架构师     | 简历深度诊断、高难度面试模拟 |
| **10年+**  | 技术专家/技术经理    | 简历亮点提炼、管理面模拟   |

### 2.2 用户场景

**场景一：跳槽前诊断**
> 小明工作 3 年，想跳槽去大厂。他上传简历，输入"Java 高级开发工程师 - 字节跳动"，AI 给出匹配度
> 65%，告诉他缺高并发项目和系统设计能力。他根据建议优化简历，一周后再测，匹配度到了 80%。

**场景二：面试前训练**
> 小红收到面试通知，她用平台模拟面试，AI 基于她的简历和职位要求提问。第一轮回答不理想，AI
> 给出反馈建议。练了两轮后，她对面试信心大增。

**场景三：面试复盘**
> 小红面试结束后，查看面试总结报告，发现自己在"系统设计"维度得分偏低。她针对这个方向重点准备，三天后参加二面，顺利通过。

### 3.2 简历管理

#### 3.2.1 上传简历

| 项目   | 说明                 |
|------|--------------------|
| 格式   | PDF（优先）、Word（docx） |
| 大小限制 | ≤ 10MB             |
| 页数限制 | ≤ 10 页             |
| 上传方式 | 本地文件选择，拖拽上传        |
| 存储   | MinIO 对象存储         |

**上传后处理流程：**

```
用户上传 PDF
    ↓
MinIO 存储（原始文件备份）
    ↓
百炼文档解析 → 提取纯文本
    ↓
AI 提取结构化信息（姓名、工作年限、技术栈、项目经历、教育背景）
    ↓
存入 MySQL（简历结构化数据）
    ↓
文本切片 → 向量化 → 存入 pgvector（用于后续面试模拟 RAG）
```

#### 3.2.2 简历列表

- 卡片展示：简历名称、上传时间、目标职位、匹配度（如有）
- 默认按上传时间倒序
- 操作：查看、删除、设为默认

#### 3.2.3 简历详情

展示结构化解析结果：

- 基本信息（姓名、工作年限、学历）
- 技术栈清单
- 项目经历列表
- 工作经历列表
- 教育背景
- 原始 PDF 预览（内嵌 PDF 查看器）

### 3.4 简历评估报告（核心功能 P0）

#### 3.4.1 触发方式

用户选择简历 → 选择目标职位 → 点击"生成评估报告"

#### 3.4.2 报告生成流程

```
用户点击"生成评估报告"
    ↓
后台将简历结构化数据 + 目标职位 JD 组装成 Prompt
    ↓
调用 LLM 生成分析报告
    ↓
报告结构化解析（匹配度、技术栈、亮点、短板）
    ↓
存入 MySQL（report 表）
    ↓
SSE 流式输出到前端，逐段渲染
```

#### 3.4.3 报告内容

**第一部分：匹配度总览**

```
┌─────────────────────────────────────┐
│  🔗 匹配度：72%                      │
│  简历 vs Java 高级开发工程师 - 字节    │
│                                      │
│  匹配度高：技术栈匹配 ✓               │
│  项目经验匹配 ✓                      │
│  工作年限匹配 ✓                      │
│                                      │
│  待提升：系统设计能力待加强 ✗          │
│  高并发项目经验不足 ✗                 │
└─────────────────────────────────────┘
```

**第二部分：技术栈分析**

| 维度      | 详情                                    |
|---------|---------------------------------------|
| 简历中技术栈  | Java、Spring Boot、MySQL、Redis、RabbitMQ |
| 职位要求技术栈 | Java、Spring Cloud、微服务、高并发、分布式         |
| 完全匹配    | Java、Spring 体系                        |
| 部分匹配    | 微服务（简历有但深度不够）                         |
| 缺失      | 高并发、分布式事务、性能优化                        |
| 建议      | 补充高并发项目经验或系统设计能力                      |

**第三部分：亮点提炼**

- 简历中最吸引面试官的 3-5 个点
- 建议在面试中重点展开的方向

**第四部分：短板提醒**

- 简历中可能被面试官 challenge 的点
- 为什么这是短板
- 建议如何弥补或规避

#### 3.4.4 报告历史

- 每次生成报告自动保存
- 报告列表：简历名称、职位名称、匹配度、生成时间
- 支持查看历史报告，对比不同时间点的匹配度变化

### 3.5 AI 模拟面试（核心功能 P0）

#### 3.5.1 触发方式

在评估报告页或简历详情页 → 点击"开始模拟面试"

#### 3.5.2 面试模式（三面制）

面试分三轮进行，从基础到深入，模拟真实面试流程：

| 轮次  | 名称   | 定位                     | 每轮题数 |
|-----|------|------------------------|------|
| 第一轮 | 技术一面 | 基础技术能力（语言基础、框架用法、项目基础） | 10 题 |
| 第二轮 | 技术二面 | 深入技术能力（底层原理、性能优化、复杂场景） | 10 题 |
| 第三轮 | 技术三面 | 综合技术能力（架构设计、技术选型、开放题）  | 10 题 |

#### 3.5.3 面试流程

```
用户选择简历+职位 → 点击"开始面试"
    ↓
技术一面（Q1-Q10）
    ├── AI 逐题提问（SSE 流式输出）
    ├── 用户输入回答 → 点击"下一题"
    ├── AI 给出反馈 + 评分
    └── 10题完成 → 一面总结 + 评分
    ↓
用户选择"继续二面"或"结束面试"
    ↓
技术二面（Q1-Q10）+ 二面总结 + 评分
    ↓
用户选择"继续三面"或"结束面试"
    ↓
技术三面（Q1-Q10）+ 三面总结 + 评分
    ↓
生成最终面试总结报告（三轮汇总）
```

**中断恢复规则：**

- 面试中主动退出 → 保存进度，标记为"进行中"
- 1 小时内再次进入 → 从断点处继续，不丢失已答题目
- 超过 1 小时 → 标记为"已过期"，用户只能查看历史记录
- 用户点击"结束面试" → 主动结束，生成已有题目的总结报告

#### 3.5.4 面试总结报告

- 面试时长、总问题数
- 三轮分别评分 + 综合评分
- 各维度评分（技术深度、项目理解、表达清晰度）
- 答得好的问题（标记）
- 答得不好的问题（标记 + 参考答案）
- 建议重点复习的方向

#### 3.5.5 面试历史

- 每次面试记录保存
- 列表：面试时间、模式、问题数量、综合评分
- 支持回看（查看完整对话记录 + 面试总结）

### 3.6 API Key 与限额管理

#### 3.6.1 价值

防止用户白嫖 API 调用成本，同时给高频用户提供不限量的通道。

#### 3.6.2 免费层（默认）

使用平台提供的 DeepSeek API Key，每天有限额：

| 功能     | 每日限额           |
|--------|----------------|
| 评估报告生成 | 3 次            |
| 模拟面试   | 1 次（三面制，30题全包） |
| 简历上传   | 不限             |
| 面试历史查看 | 不限             |

超额后提示："今日评估报告次数已用完，请明日再试或配置自己的 API Key 以解锁不限量使用。"

#### 3.6.3 Pro 层（用户自配 API Key）

用户在个人设置中配置自己的 API Key（支持 DeepSeek / 通义千问 / GLM 等多种服务商）：

| 权限   | 说明                |
|------|-------------------|
| 所有功能 | 不限量               |
| 服务商选择 | 用户可选择 DeepSeek / 通义千问 / GLM 等 |
| 模型选择 | 用户可自选模型版本         |
| 费用   | 消耗用户自己的 Key，平台零成本 |

#### 3.6.4 用户侧体验

```
个人设置 → API Key
├── 当前状态：使用平台默认额度（每日3次报告+1次面试）
└── [开启专业模式]
    └── 输入你的 DeepSeek API Key
        └── 开启后：不限量使用，费用消耗你的 Key
```

### 6.3 RAG 链路设计

```
简历 PDF
    ↓
百炼文档解析 → 纯文本
    ↓
TokenTextSplitter 切片（chunk_size=500, overlap=50）
    ↓
BGE embedding 向量化 → 存入 pgvector（status="简历"）
    ↓
面试提问时：用户问题 → 向量检索 → 召回简历相关片段
    ↓
+ 目标职位 JD（同样向量化存入 pgvector，status="职位"）
    ↓
组装 Prompt → LLM 生成面试问题
```

### 6.4 Agent 编排

沿用现有 Advisor Chain 模式，新增 Resume 场景的 Advisor：

```
input → SafeValidAdvisor → ReReadingAdvisor
    → MessageChatMemoryAdvisor（面试对话记忆）
    → RetrievalAugmentationAdvisor（简历+JD RAG）
    → LLM
    → SafeValidAdvisor（输出检测）
    → SSE 流式输出
```

## 9. 附录

### 9.1 关键 Prompt 设计

**简历评估报告 Prompt 核心要点：**

- 角色：资深技术面试官 + 简历顾问
- 输入：简历结构化数据 + 目标职位 JD
- 要求：输出匹配度评分、技术栈对比、亮点提炼、短板提醒
- 约束：只做诊断分析，不编造简历没有的内容

**面试模拟 Prompt 核心要点：**

- 角色：目标公司的技术面试官
- 知识来源：简历内容 + 目标职位 JD（RAG 检索）
- 行为：先问一个开放式问题，根据回答深度决定追问还是换题
- 反馈：用户回答后判断质量，给出改进建议
- 约束：不要直接告诉答案，引导用户思考

### 9.2 多模型服务商支持

基于 OpenAI 兼容 API 协议，支持 DeepSeek / 通义千问 / GLM 等多种模型服务商。
用户可在设置页面自由切换，ApiKeyRoutingAdvisor 根据 `api_base_url` 和 `api_model` 动态路由到对应端点。

> 以下内容体现企业级项目的工程水准，是面试时展示技术深度的关键。

### 10.1 架构设计

#### 10.1.1 微服务架构

采用单应用多模块的**模块化架构**（Monolith-first），便于演示和部署，但模块划分遵循微服务的设计原则：

```
offer-agent/
├── offer-common/          # 公共模块：工具类、统一响应体、异常定义
├── offer-auth/            # 认证模块：注册/登录/Sa-Token+JWT
├── offer-resume/          # 简历模块：上传/解析/CRUD
├── offer-report/          # 报告模块：评估报告生成
├── offer-interview/       # 面试模块：AI 模拟面试
├── offer-ai-core/         # AI 核心模块：Advisor Chain、RAG、LLM 调用
│   ├── advisor/           # Advisor 编排
│   ├── rag/               # 检索增强
│   └── memory/            # 对话记忆
└── offer-api/             # API 层：Controller + DTO 转换
```

**模块化原则：**

- 每个模块有独立的 `service`、`repository`、`domain`
- 模块间通过接口依赖，不直接依赖实现
- `offer-ai-core` 可独立抽取为微服务（对标 ehr-agent 经验）

#### 10.1.2 领域驱动设计（DDD）

核心限界上下文划分：

| 限界上下文     | 聚合根              | 说明            |
|-----------|------------------|---------------|
| **认证上下文** | User             | 用户注册、登录、会话管理  |
| **简历上下文** | Resume           | 简历上传、解析、结构化存储 |
| **职位上下文** | TargetPosition   | 目标职位管理、JD 解析  |
| **评估上下文** | Report           | 评估报告生成、历史查看   |
| **面试上下文** | InterviewSession | 面试对话、评分、总结    |

#### 10.1.3 统一响应体

```java
// 全局统一返回格式
public class ApiResult<T> {
    private int code;        // 200=成功, 其他=错误码
    private String message;  // 提示信息
    private T data;          // 响应数据
    private String traceId;  // 链路追踪 ID
}

// 分页统一格式
public class PageResult<T> {
    private List<T> records;
    private long total;
    private int page;
    private int size;
}
```

#### 10.1.4 全局异常处理

```java

@RestControllerAdvice
public class GlobalExceptionHandler {
    // 业务异常 → 已知错误，友好提示
    // 参数校验异常 → 字段级错误提示
    // 系统异常 → 统一 500，traceId 可查
    // AI 服务异常 → 降级返回兜底文案
}
```

### 10.4 安全体系

#### 10.4.1 认证与授权

| 层次  | 方案                     | 说明                                   |
|-----|------------------------|--------------------------------------|
| 认证  | Sa-Token + JWT 双 Token | Access Token 有效期 2h，Refresh Token 7d |
| 授权  | 接口级鉴权                  | 用户只能访问自己的资源                          |
| 防越权 | 数据权限拦截                 | 查询时自动注入 user_id 条件                   |

#### 10.4.2 AI 安全

| 层次    | 方案                                  |
|-------|-------------------------------------|
| 输入过滤  | SafeValidAdvisor：敏感词、脚本注入、Prompt 注入 |
| 输出过滤  | SafeValidAdvisor：敏感内容检测             |
| 知识库隔离 | 每个用户的简历向量按 user_id 过滤               |
| 对话隔离  | 面试会话按 user_id + session_id 隔离       |

#### 10.4.3 数据安全

- 密码使用 BCrypt 加密
- 用户敏感信息（手机号、邮箱）存储加密
- 简历文件 MinIO 访问使用临时签名 URL（有效期 30 分钟）
- API 接口防刷：限流（Rate Limiting）
